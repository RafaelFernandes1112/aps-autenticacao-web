## 1.2 Navegador (browser)
 
O navegador é o software de apoio executado no dispositivo do usuário que serve de interface entre ele e a aplicação Web. Ele é invocado por uma ação do usuário, como digitar o endereço da aplicação, seguir um link ou enviar um formulário, e, a partir dela, conduz toda a comunicação com o servidor.
 
No software projetado, cujo escopo se restringe ao back-end (item 2.1.2), a tela de login pertence ao cliente: é uma página com o formulário de login, em HTML, CSS e JavaScript, que o navegador carrega antes da autenticação. Para exibi-la, o navegador constrói a árvore do documento (DOM) e a árvore de estilos (CSSOM), combina as duas na árvore de renderização, calcula a posição e o tamanho de cada elemento (layout) e desenha a página na tela (paint), deixando o formulário pronto para uso.
 
Ao clicar em "Entrar", o código JavaScript da página lê o identificador (login ou e-mail) e a senha digitados e monta uma requisição HTTP POST para o endpoint /api/login da API de Autenticação, com as credenciais no corpo em formato JSON e o cabeçalho Content-Type: application/json, conforme o contrato definido no item 2.1.5. Para enviá-la, o navegador interpreta a URL da API, do tipo https://auth.exemplo.com.br:8443/api/login, obtém o endereço IP do servidor por meio do DNS (item 1.3) e estabelece uma conexão TCP protegida por TLS na porta 8443, validando o certificado digital apresentado pelo servidor (item 1.4). A requisição segue por essa conexão, de modo que as credenciais trafegam cifradas entre o navegador e o servidor (ANTHROPIC, 2026b).
 
O resultado do processamento depende do código de status da resposta. Em caso de sucesso (200 OK), o navegador recebe o objeto JSON com a identificação do usuário, com os campos id e nome, que o código da página utiliza para continuar o fluxo com o usuário autenticado. A API não cria sessão nem envia cookies, pois sua função se limita a verificar as credenciais e devolver essa identificação (item 2.1.1). Em caso de falha de autenticação (401 Unauthorized), o navegador exibe ao usuário a mensagem genérica de erro; e, se a requisição estiver malformada (400 Bad Request), indica que os dados enviados são inválidos. Assim, o navegador produz dois tipos de resultado: as requisições HTTP enviadas ao servidor e a página renderizada que o usuário vê (ANTHROPIC, 2026d).
