## 1.5 Servidor web
 
O servidor web é o primeiro componente do lado do servidor a receber a requisição do navegador e o único exposto à internet (item 1.1). No ambiente adotado, essa função é exercida pelo Nginx, que atua ao mesmo tempo como servidor de conteúdo estático e como proxy reverso. O Nginx é iniciado como um serviço do sistema operacional quando o servidor é ligado: um processo mestre lê e valida o arquivo de configuração e cria os processos de trabalho (workers), que efetivamente atendem as requisições. Cada worker segue um modelo orientado a eventos, capaz de tratar muitas conexões simultâneas sem criar um processo ou uma thread para cada uma (NGINX, 2026a).
 
O Nginx permanece escutando a porta 443 e é invocado quando o navegador abre uma conexão TCP com ela. Nesse momento, ele conduz o lado servidor do handshake TLS descrito no item 1.4, usando o certificado digital e a chave privada indicados na sua configuração. Esse processo é chamado de terminação TLS: o Nginx decifra o tráfego recebido, de modo que os componentes internos não precisam lidar com criptografia (NGINX, 2026b). Ele também escuta a porta 80, mas apenas para redirecionar quem acessar a aplicação por HTTP para o endereço HTTPS.
 
Depois de decifrar a requisição, o Nginx seleciona o bloco de configuração correspondente ao domínio informado no cabeçalho Host e, dentro dele, a regra (location) que corresponde ao caminho solicitado. Requisições de arquivos estáticos da interface, como a página de login e seus arquivos CSS e JavaScript, são atendidas diretamente: o Nginx lê o arquivo no disco e o devolve com o cabeçalho de tipo de conteúdo adequado. Requisições dinâmicas, como o POST /login, são encaminhadas ao servidor de aplicação pela diretiva proxy_pass, por HTTP na porta 8080 da rede interna (item 1.6) (NGINX, 2026a). Ao encaminhar, o Nginx acrescenta cabeçalhos como X-Forwarded-For e X-Forwarded-Proto, que informam à aplicação o endereço IP original do cliente e o fato de a requisição ter chegado por HTTPS, informações que, de outro modo, se perderiam na passagem pelo proxy.
 
O servidor web produz, portanto, um de dois resultados: a resposta estática gerada por ele mesmo, ou a requisição repassada ao servidor de aplicação, cuja resposta ele recebe, cifra novamente pelo canal TLS e devolve ao navegador, podendo acrescentar cabeçalhos de segurança como o Strict-Transport-Security (item 1.4). Cada requisição atendida também é registrada nos logs de acesso e de erro. Por concentrar a terminação TLS e ser o único ponto de entrada, o Nginx mantém o servidor de aplicação e o banco de dados fora do alcance direto da internet (ANTHROPIC, 2026a).
