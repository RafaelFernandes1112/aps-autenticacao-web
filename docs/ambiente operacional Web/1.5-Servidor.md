## 1.5 Servidor web
 
O servidor web é o componente do lado do servidor que recebe as conexões dos clientes, conduz o protocolo HTTP e devolve as respostas. No ambiente adotado, essa função é exercida pelo Tomcat, embutido na própria aplicação Spring Boot (item 2.1.4): não há um servidor web instalado à parte nem um proxy reverso à frente da aplicação. O Tomcat é iniciado junto com a aplicação, quando ela é executada com o comando java -jar. Durante a inicialização, o Spring Boot cria o servidor, lê as propriedades de configuração e abre a porta 8443 com TLS habilitado, registrando no log uma mensagem que indica a porta e o protocolo em uso (SPRING, 2026).
 
O Tomcat é invocado quando o navegador abre uma conexão TCP com a porta 8443. O componente do Tomcat que atende a porta, chamado conector, aceita a conexão e conduz o lado servidor do handshake TLS descrito no item 1.4, usando o certificado e a chave privada do arquivo keystore.p12, cuja senha é fornecida à aplicação pela variável de ambiente KEYSTORE_PASSWORD. Esse processo é chamado de terminação TLS: o Tomcat decifra o tráfego recebido, de modo que a lógica da aplicação recebe a requisição já decifrada e não precisa lidar com criptografia (SPRING, 2026).
 
Depois de decifrar os bytes, o Tomcat interpreta a mensagem HTTP, lendo a linha inicial, os cabeçalhos e o corpo, e monta um objeto que representa a requisição. Em seguida, atribui o processamento a uma thread do seu pool, de modo que várias requisições podem ser atendidas em paralelo, e entrega a requisição ao servlet registrado pela aplicação, o DispatcherServlet do Spring MVC, que dá início ao processamento descrito no item 1.6. Como o software projetado não serve páginas nem arquivos estáticos, todas as requisições recebidas seguem esse caminho, e uma requisição a um caminho sem tratamento recebe uma resposta de erro, como 404 (Not Found).
 
O resultado do processamento do servidor web é a resposta HTTP devolvida ao navegador. Quando a aplicação conclui o processamento, o Tomcat escreve na conexão a linha de status, os cabeçalhos e o corpo JSON produzidos por ela, cifra esses dados pelo canal TLS e os envia ao navegador; a thread é então liberada para atender outra requisição, e a conexão pode ser mantida aberta para as requisições seguintes. Por ser o único componente que escuta a rede, o Tomcat é o ponto de entrada da aplicação, e o banco de dados, que não abre nenhuma porta, permanece fora do alcance direto da internet (ANTHROPIC, 2026d).
