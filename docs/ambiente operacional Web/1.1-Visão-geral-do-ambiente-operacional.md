# 1 Ambiente operacional de uma aplicação Web
 
Esta seção descreve o ambiente operacional envolvido na execução de uma aplicação Web, isto é, o conjunto de softwares de apoio que participam do processamento de uma requisição, do navegador do usuário até o banco de dados. Para cada componente, explica-se como ele é invocado e quais resultados produz. A descrição adota a mesma pilha tecnológica do projeto apresentado na Seção 2: [navegador moderno, como o Google Chrome], [Nginx versão] como servidor web e proxy reverso, [Spring Boot versão, com Tomcat embutido] como servidor de aplicação e [SQLite versão] como sistema gerenciador de banco de dados embutido, com a comunicação protegida por HTTPS. Como fio condutor, utiliza-se a própria requisição de autenticação do software projetado (POST /login). O item 1.1 apresenta a visão geral do ambiente; os itens 1.2 a 1.7 detalham cada componente (navegador, DNS, protocolos HTTP/HTTPS e TLS, servidor web, servidor de aplicação e SGBD); e o item 1.8 reúne tudo no fluxo completo de processamento de uma requisição (ANTHROPIC, 2026a).
 
## 1.1 Visão geral do ambiente operacional
 
**Autor(a):** Rafael F. da Silva · **Revisor(a):** Caique Duarte · **Referências:** (KUROSE; ROSS, 2021); (ANTHROPIC, 2026a)
 
O ambiente operacional de uma aplicação Web é formado por componentes distribuídos em três partes, o lado do cliente, a infraestrutura de rede e o lado do servidor, conforme ilustrado na Figura 1. No lado do cliente está o navegador (item 1.2), executado no dispositivo do usuário e ponto de entrada de toda interação. Antes de se comunicar com o servidor, o navegador consulta o sistema de nomes de domínio, o DNS, para obter o endereço IP correspondente ao domínio da aplicação (item 1.3). Com esse endereço, estabelece uma conexão segura com o servidor web por HTTPS, na porta 443, por meio dos protocolos descritos no item 1.4.
 
No lado do servidor, o servidor web Nginx (item 1.5) é o único componente exposto à internet. Ele recebe as conexões dos clientes, entrega os arquivos estáticos da interface e encaminha as requisições dinâmicas ao servidor de aplicação Spring Boot, com Tomcat embutido (item 1.6), por HTTP na porta 8080 da rede interna. O servidor de aplicação executa a lógica de autenticação e, quando precisa de dados, utiliza o SQLite (item 1.7), um sistema gerenciador de banco de dados embutido, que funciona como uma biblioteca dentro do próprio processo da aplicação e armazena os dados em um único arquivo em disco, sem servidor de banco separado nem comunicação pela rede. A resposta percorre o caminho inverso até o navegador, e o percurso completo de uma requisição é detalhado no item 1.8 (KUROSE; ROSS, 2021; ANTHROPIC, 2026a).
