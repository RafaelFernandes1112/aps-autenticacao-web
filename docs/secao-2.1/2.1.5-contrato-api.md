# 2.1.5 Contrato da interface de autenticação (API)

Autor(a): Caique Duarte · Revisor(a): [a definir] · Referências: (FIELDING; NOTTINGHAM; RESCHKE, 2022)

Tabela 2 – Contrato da interface de autenticação

| Campo                 | Valor                                                                        |
| --------------------- | ---------------------------------------------------------------------------- |
| Endpoint              | `POST /api/login`                                                            |
| Requisição            | `{ "identificador": "maria@exemplo.com", "senha": "..." }` (login ou e-mail) |
| Sucesso               | `200 OK` com `{ "id": 42, "nome": "Maria Souza" }`                           |
| Requisição malformada | `400 Bad Request` com `{ "erro": "Requisição inválida" }`                    |
| Falha de autenticação | `401 Unauthorized` com `{ "erro": "Credenciais inválidas" }`                 |

Fonte: Elaborado pelos autores (2026).

O 400 é usado quando falta um campo ou o JSON é inválido. O 401 é o mesmo para usuário inexistente e senha errada (RNF03).
